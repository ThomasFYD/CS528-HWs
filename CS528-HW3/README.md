# CS528 Homework 3: HTTP Services and Pub/Sub

Author: Yide Fang

This project uses two Python services to serve the HTML dataset from [Homework 2](../CS528-HW2/README.md) and record requests from the countries specified in the assignment.

1. A Google Cloud Function accepts HTTP GET and POST requests, reads files from Cloud Storage, returns HTTP status codes, and publishes forbidden-country events to Pub/Sub.
2. A subscriber running on a Mac receives those events, prints them, and appends them to one JSONL object in the same bucket.

Both services use the same dedicated service account. The Mac service obtains short-lived impersonated credentials without downloading a service-account key or using `gcloud auth application-default login`.

```text
Client -> Cloud Function -> Cloud Storage: data/*.html
                    |
                    +-> Pub/Sub -> Mac subscriber -> Cloud Storage: hw3-logs/forbidden-requests.jsonl
```

## HTTP behavior

| Request | Result |
| --- | --- |
| `GET /data/0.html` | Original file bytes and HTTP 200. |
| `GET /cs528-hw2-yf-2026/data/0.html` | The same object; the bucket prefix is optional. |
| `POST /` with JSON `{"filename":"data/0.html"}` | Original file bytes and HTTP 200. |
| GET/POST for a missing object | HTTP 404. |
| PUT, DELETE, HEAD, OPTIONS, PATCH | HTTP 501. HEAD has no response body. |
| CONNECT, TRACE at the public endpoint | Platform-generated HTTP 405; see the explanation below. |
| GET/POST with a forbidden `X-country` value | Publish an event and return the assignment's HTTP 400. |
| Invalid POST payload | HTTP 400. |
| Storage/authentication failure | HTTP 500. |
| Failure to confirm publication of a forbidden-country event | HTTP 503; the requested file is not served. |

The handler serves only objects under `data/`. Each error generated by the handler emits a plain-text print line and a structured JSON line to stdout for Cloud Logging.

The assignment's forbidden-country list is **North Korea, Iran, Cuba, Myanmar, Iraq, Libya, Sudan, Zimbabwe, and Syria**. Country matching ignores case and normalizes whitespace. The header simulates the request's origin; it is not verified geolocation or a current legal sanctions list. Unsupported-method handling runs before country filtering.

### CONNECT and TRACE

Google documents that [Cloud Run does not forward CONNECT and TRACE to services](https://docs.cloud.google.com/run/docs/known-issues#http-methods). In the recorded public-endpoint tests, both returned HTTP 405 with Google-generated error pages. The rejection occurs at Google's managed HTTP frontend, before the Python function is invoked.

Consequently, the function cannot return its configured 501 or produce its own print/structured logs for those cloud requests. Local Functions Framework tests reach the handler directly and return 501 for both methods. These local results are distinct from the observed cloud 405 responses. The implementation retains its generic 501 branch; no VM gateway is used. CONNECT/TRACE remain documented platform exceptions to Step 3, not successful public 501 tests.

## Configure the project

Use Python 3.12, the Google Cloud CLI (`gcloud`), and `curl`. Run the commands from `CS528-HW3/` unless a step says otherwise. Set these variables in each terminal that needs them:

```bash
export HW3_PROJECT="dazzling-seat-508219-j3"
export HW3_BUCKET="cs528-hw2-yf-2026"
export HW3_REGION="us-central1"
export HW3_USER="fangyd@bu.edu"
export HW3_SA="cs528-hw3-sa@${HW3_PROJECT}.iam.gserviceaccount.com"
export HW3_TOPIC="cs528-hw3-forbidden"
export HW3_SUB="cs528-hw3-forbidden-sub"
```

Authenticate the CLI and enable the required APIs:

```bash
gcloud auth login "$HW3_USER"
gcloud config set project "$HW3_PROJECT"
gcloud services enable \
  cloudfunctions.googleapis.com run.googleapis.com \
  cloudbuild.googleapis.com artifactregistry.googleapis.com \
  pubsub.googleapis.com storage.googleapis.com logging.googleapis.com \
  iam.googleapis.com iamcredentials.googleapis.com \
  --project="$HW3_PROJECT"
```

The following creation commands are for initial setup. Skip them when the named resources already exist:

```bash
gcloud iam service-accounts create cs528-hw3-sa \
  --display-name="CS528 HW3 Service Account" --project="$HW3_PROJECT"
gcloud pubsub topics create "$HW3_TOPIC" --project="$HW3_PROJECT"
gcloud pubsub subscriptions create "$HW3_SUB" \
  --topic="$HW3_TOPIC" --ack-deadline=60 --project="$HW3_PROJECT"
```

Grant the runtime account read access to the dataset, conditional write access to the log prefix, and access to the topic and subscription. Grant the human account permission to attach and impersonate that identity:

```bash
gcloud storage buckets add-iam-policy-binding "gs://${HW3_BUCKET}" \
  --member="serviceAccount:${HW3_SA}" \
  --role=roles/storage.objectViewer --condition=None

HW3_LOG_EXPR="resource.name.startsWith('projects/_/buckets/${HW3_BUCKET}/objects/hw3-logs/')"
gcloud storage buckets add-iam-policy-binding "gs://${HW3_BUCKET}" \
  --member="serviceAccount:${HW3_SA}" --role=roles/storage.objectUser \
  --condition="title=hw3-log-write,expression=${HW3_LOG_EXPR}"

gcloud pubsub topics add-iam-policy-binding "$HW3_TOPIC" \
  --member="serviceAccount:${HW3_SA}" --role=roles/pubsub.publisher \
  --project="$HW3_PROJECT"
gcloud pubsub subscriptions add-iam-policy-binding "$HW3_SUB" \
  --member="serviceAccount:${HW3_SA}" --role=roles/pubsub.subscriber \
  --project="$HW3_PROJECT"

gcloud iam service-accounts add-iam-policy-binding "$HW3_SA" \
  --member="user:${HW3_USER}" --role=roles/iam.serviceAccountUser \
  --project="$HW3_PROJECT"
gcloud iam service-accounts add-iam-policy-binding "$HW3_SA" \
  --member="user:${HW3_USER}" --role=roles/iam.serviceAccountTokenCreator \
  --project="$HW3_PROJECT"
```

Check the service account's access:

```bash
gcloud storage objects describe "gs://${HW3_BUCKET}/data/0.html" \
  --account="$HW3_USER" --impersonate-service-account="$HW3_SA" \
  --project="$HW3_PROJECT"
```

## Deploy the cloud function

From `CS528-HW3/`, with the configuration variables set:

```bash
gcloud functions deploy cs528-hw3-files \
  --gen2 --runtime=python312 --region="$HW3_REGION" \
  --project="$HW3_PROJECT" --source=cloud_function --entry-point=get_file \
  --trigger-http --allow-unauthenticated --service-account="$HW3_SA" \
  --set-env-vars="BUCKET_NAME=${HW3_BUCKET},PROJECT_ID=${HW3_PROJECT},TOPIC_ID=${HW3_TOPIC}" \
  --memory=256Mi --timeout=60s --min-instances=0 --max-instances=2
```

The function uses its attached service account for Storage and Pub/Sub. The identity used by Cloud Build during deployment is separate from the runtime identity.

## Run the Mac subscriber

In terminal A, from `CS528-HW3/`, with the configuration variables set:

```bash
python3 -m venv local_service/.venv
local_service/.venv/bin/python -m pip install -r local_service/requirements.txt
mkdir -p results
local_service/.venv/bin/python -u local_service/subscriber.py \
  --project="$HW3_PROJECT" --bucket="$HW3_BUCKET" \
  --subscription="$HW3_SUB" --account="$HW3_USER" \
  --service-account="$HW3_SA" \
  2>&1 | tee -a results/subscriber.txt
```

Leave this terminal running while testing from terminal B. For a new event, the output includes `FORBIDDEN`, `APPENDED`, and `ACKED`. Repeated events already present in the log produce `ALREADY_STORED`. Stop the process with Ctrl+C.

The credential adapter calls the installed SDK's hidden `gcloud config config-helper` command with explicit account and impersonation flags, captures the token and expiration in memory, and supplies refreshable credentials to both Python clients. SDK changes may require updating this adapter. This is normal CLI login followed by impersonation; it does not use Application Default Credentials login.

The log writer reads the existing JSONL object and uploads the previous contents plus the new event. Generation-match preconditions protect against concurrent overwrites, and persisted event IDs prevent duplicate lines after redelivery or restart. Messages are acknowledged only after persistence. This is application-level deduplication, not a claim of exactly-once Pub/Sub delivery.

## Verify the services

In terminal B, from `CS528-HW3/`:

```bash
HW3_URL="https://cs528-hw3-files-sw2da6eioq-uc.a.run.app"
mkdir -p results

curl -sS -o results/get-body.html -w 'GET: %{http_code}\n' \
  "$HW3_URL/data/0.html"
curl -sS -H 'Content-Type: application/json' \
  --data '{"filename":"data/0.html"}' \
  -o results/post-body.html -w 'POST: %{http_code}\n' "$HW3_URL/"
curl -sS -o results/missing-body.txt -w 'Missing: %{http_code}\n' \
  "$HW3_URL/data/not-a-real-hw3-file.html"
curl --http1.1 -sS -X PUT --data-binary '' \
  -o results/put-body.txt -w 'PUT: %{http_code}\n' "$HW3_URL/data/0.html"
curl -sS -H 'X-country: Iran' \
  -o results/iran-body.txt -w 'Iran: %{http_code}\n' "$HW3_URL/data/0.html"
```

Expected statuses are 200, 200, 404, 501, and 400 respectively. The empty PUT body makes curl send `Content-Length: 0`; the original HTTP/1.1 request without a body length received frontend 411 before this correction.

Run the complete recorded-response checks:

```bash
python3 scripts/verify_http_methods.py
python3 scripts/verify_country_flow.py
```

The HTTP-method script reports `REVIEW` and exits nonzero for CONNECT/TRACE because it compares actual cloud responses against the assignment's 501 requirement. It preserves the real responses rather than marking 405 as a pass.

The country script sends nine forbidden-country GET requests, one forbidden-country POST, and one allowed-country GET. It waits for ten new events to appear in the log. Keep terminal A running. If the delivery check times out, restore the subscriber and recheck the same run without sending more HTTP requests:

```bash
# Set this to the Results directory printed by your own run.
HW3_RUN_DIR="results/country-tests-<timestamp-from-your-run>"
python3 scripts/verify_country_flow.py --recheck "$HW3_RUN_DIR"
```

## Scope

The HW2 bucket retained public object-read access, so direct public bucket URLs bypass the function's country filter and log objects inherit public read access. The application only exposes `data/` through its file endpoint. Rewriting and scanning a single JSONL object is suitable for this small homework log, not a high-volume logging service.
